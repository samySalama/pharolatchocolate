# Development Guide — Pharolat Chocolate Website

This guide explains how the website is built, which files matter most, how they interact, and how to change the project safely. It is written for a future developer or an AI coding assistant. Read it before making changes. For setup and editing instructions, read `README.md` first.

---

## 1. Architecture at a glance

The site is a **single static page** with three source files and one data file:

```
index.html   ──loads──►  styles.css        (presentation)
     │
     └──loads──►  script.js  (behaviour + data)
                    │
                    ├─ PRODUCTS / GROUPS / SHOWCASE / PRICES   (data, top of file)
                    ├─ renderCollections()  → builds product cards into #product-groups
                    ├─ renderShowcase()     → builds the photo strip into #showcase-track
                    ├─ applyCopy()          → updates every bilingual text, alt, aria, title
                    └─ setLanguage(lang)    → sets language, then re-renders dynamic parts
```

There is **no build step, no bundler, no framework and no server code**. The browser reads the files directly. Everything that is not generated by JavaScript is written in `index.html`.

### Data flow when the page loads
1. `index.html` is parsed. The HTML contains empty containers (`#product-groups`, `#showcase-track`) and the fixed text.
2. `script.js` runs (it is loaded with `defer`, so the HTML is ready first).
3. `setLanguage('ar')` runs. It calls, in order:
   - `applyCopy()` — sets `<html lang/dir>`, fills every `[data-copy-en][data-copy-ar]` element, every `[data-alt-en][data-alt-ar]` image alt, every `[data-aria-en][data-aria-ar]` label, the title and the meta tags, and the language-button label.
   - `renderCollections()` — generates the product cards from `GROUPS` and `PRODUCTS`.
   - `renderShowcase()` — generates the four showcase photos from `SHOWCASE`.
4. The user clicks **AR / EN**. The same `setLanguage()` is called with the other language. Everything is regenerated, so no stale text remains.

## 2. File-by-file reference

### `index.html` — structure and fixed text
Sections in order: skip link → header → `<main>` (hero, showcase, collection, story, closing) → footer → mobile order bar → script.

Important conventions:
- **`data-copy-en` / `data-copy-ar`** on an element → its text is replaced on language change. The visible text between the tags is the Arabic default.
- **`data-alt-en` / `data-alt-ar`** on an `<img>` → its `alt` is replaced on language change.
- **`data-aria-en` / `data-aria-ar`** on an element → its `aria-label` is replaced on language change.
- **Empty containers** `#product-groups` and `#showcase-track` are filled by JavaScript. Do not put product markup inside them by hand.
- **Section IDs** `#collection` and `#story` are link targets (header navigation and skip link). Keep them.
- **Hard-coded values** in this file: the WhatsApp number (in five `href`s and the footer text), the Instagram handle (in the footer, twice), the two price mentions in the collection heading, and the Google Fonts link. If any of these change, update them here as well as in `script.js`. See the README, sections 7.3 and 11.

### `styles.css` — presentation
Structure:
1. `:root` — design tokens (colours, font stacks, spacing, container width, section padding).
2. Base rules (`*`, `html`, `body`, images, focus styles).
3. Components in page order: header, buttons, hero, section scaffolding, showcase, collection and product cards, story, closing band, footer, mobile order bar.
4. A narrow-phone block (`max-width: 399px`) that tightens the header.
5. Breakpoints: `min-width: 600px` (two product columns, wider showcase), `min-width: 900px` (desktop layout, three product columns, hides the mobile order bar), `min-width: 1200px` (four product columns).
6. `prefers-reduced-motion: reduce` — shortens transitions and disables smooth scrolling.

Conventions:
- **Use the tokens.** Colours and fonts come from `:root` variables. Do not hard-code new colours in components.
- **Logical properties are used in places** (`inset-inline-start`, `margin-inline-start`) so that layout works in both directions. Keep using them for new rules.
- **RTL/LTR overrides** use the attribute selectors `html[dir='rtl'] …` and `html[dir='ltr'] …`. Add new overrides in the same style.
- **Borders are 1–2 px, with no shadows and no gradients** (the approved design direction). Do not add decorative effects without approval.
- **Border radius is 0** for buttons, images and cards. The only rounded element is the circular brand mark in the header (`.brand-symbol`).

### `script.js` — data and behaviour
Top to bottom:
1. **Constants:** `WHATSAPP_NUMBER`, `PRICES`, `BRAND`, `IMG` (the image folder prefix).
2. **`GROUPS`** — the three collections (`id`, `en`, `ar`). Display order is the array order.
3. **`PRODUCTS`** — the 11 flavours. Each has `en`, `ar`, `group`, `photo` (or `null`) and `alt`.
4. **`SHOWCASE`** — the four unlabelled photos, each with `src`, `srcset` and bilingual `alt`.
5. **State:** `let lang` (the current language, default `'ar'`), and helpers `isEn()`, `t(obj)` (returns the English or Arabic value of a `{en, ar}` object) and `escapeAttr()`.
6. **`orderedProducts`** — products flattened in display order. Used to number the cards.
7. **`orderMessage()` and `whatsappUrl()`** — build the WhatsApp message and link.
8. **`renderCard(product)`** — returns the HTML for one card (photo or ivory plate, name, two price links).
9. **`renderCollections()`** — renders all groups into `#product-groups`.
10. **`renderShowcase()`** — renders the photo strip into `#showcase-track`.
11. **`applyCopy()`** — updates every bilingual element, the document title and the meta tags.
12. **`setLanguage(next)`** — the single entry point for language changes.
13. **`scrollShowcase(direction)`** — moves the photo strip. It reverses direction in RTL.
14. **Event listeners and start-up:** language button, showcase buttons, the year in the footer, and the first call `setLanguage('ar')`.

### `brand-logo.svg`
The brand icon, used as the browser tab icon (`<link rel="icon">`). The logo artwork was **approved and must not be changed without approval.**

### `assets/images/`
- `hero/hero-caramel-{800,1600}.webp` — the banner photo.
- `products/<flavour>-{800,1600}.webp` and `products/almond.webp` — product photos. Each card uses the `src` and `srcset` set in `PRODUCTS`.
- `carousel/still-life-{1..4}-{800,1600}.webp` — showcase photos.

All photos were converted from the supplied originals. The original PNG files and the source archive are not part of this project.

### `tests/browser_test.py`
An optional Playwright test. It loads the site in Chromium and checks: 11 cards and their names, 22 WhatsApp links with the right number and prices, language switching, the absence of old brand names, horizontal overflow at six widths in both languages, image loading and alt text, showcase controls, reduced-motion detection, the mobile order bar, and the skip link. It prints a JSON report. It contains expected values (product names, prices, number) that must be updated when those values change on purpose.

### `.gitignore`, `.nojekyll`
- `.gitignore` excludes system junk (`.DS_Store`, `Thumbs.db`).
- `.nojekyll` must stay in the root. It stops GitHub Pages from applying Jekyll processing, which would otherwise interfere with the files.

## 3. How the main components interact

| Component | Reads | Writes / affects |
|---|---|---|
| Header language button | `lang` | Calls `setLanguage()` |
| `setLanguage()` | `lang` | `<html lang/dir>`, all bilingual text, product cards, showcase |
| `renderCard()` | `PRODUCTS`, `PRICES`, `WHATSAPP_NUMBER`, `isEn()` | Card HTML, WhatsApp links |
| `orderMessage()` | `BRAND`, `PRICES`, product names, `isEn()` | WhatsApp message text |
| Showcase buttons | `#showcase-track` size, `dir` | Scroll position |
| Mobile order bar, header, hero, footer links | Static `href` in `index.html` | Open WhatsApp / Instagram |

The product **prices** affect two things: the price text on each card and the WhatsApp message. Both come from `PRICES`. The collection heading text in `index.html` is separate and must be kept in step by hand.

## 4. Safe-change rules

Follow these rules to avoid breaking existing behaviour.

1. **Never change a product, price or WhatsApp number in one place only.** Use the lists in `README.md` (sections 7.3 and 11) and update every location.
2. **Always provide both languages** for any new visible text: `data-copy-en` and `data-copy-ar` in HTML, `en` and `ar` in JavaScript.
3. **Never remove `data-copy-*`, `data-alt-*` or `data-aria-*` attributes** from elements that have them. Removing one leaves that text stuck in the wrong language.
4. **Keep the IDs `#collection`, `#story`, `#product-groups`, `#showcase-track`, `#showcase-prev`, `#showcase-next`, `#year`, `#top`.** The JavaScript and the links depend on them.
5. **Keep the selectors used by the script:** `.language-toggle`, `.language-current`, `.price-option`, `.product-name`. Renaming them requires changing `script.js` too.
6. **Do not add a product without a `group` that exists in `GROUPS`.** A product with an unknown group will not be shown.
7. **Keep `photo: null` for products with no verified photo.** Do not borrow an unrelated image.
8. **Keep every image path relative** (`assets/...`) and the file names lowercase.
9. **Do not add descriptions, ingredients or claims** without written approval.
10. **Do not add frameworks, npm packages or a build step** without approval. The project is intentionally dependency-free.
11. **Test after every change** (checklist below).
12. **Do not change the approved visual design or copy** without the business's approval. Structural or content changes need sign-off.

### Checklist after any change
- [ ] Both languages show the correct text (switch with AR / EN).
- [ ] Page title and meta description change with the language.
- [ ] All 11 product cards show; each has two price links.
- [ ] Each WhatsApp link opens with the right number, flavour, type and price.
- [ ] Layout works at 360 px and 1440 px, with no horizontal scrolling.
- [ ] Showcase previous/next buttons work.
- [ ] Browser console shows no JavaScript errors (apart from blocked external fonts when offline).
- [ ] Optional: run `tests/browser_test.py` (README section 8).

## 5. Known constraints and design decisions

- **Text-only cards** (Walnut, Hazelnut, Coffee, Dubai) are intentional until photos are approved.
- **Showcase photos are deliberately unlabelled.** Do not assign flavour names to them unless the photo clearly shows that flavour.
- **Prices are not hidden behind a cart.** Each price button opens WhatsApp directly. There is no cart, quantity field or checkout, by design.
- **The language is stored only in memory.** A page refresh returns to the default (Arabic). Storing the choice would be a new feature and needs approval.
- **The almond photo is cropped** from the original supplied photo to remove an unrelated product. Do not re-crop it without reviewing the result.
- **Product numbers on cards are generated** from display order. Changing the order of `GROUPS` or `PRODUCTS` changes the numbers.
- **Google Fonts** are loaded from the internet. Without a connection, the browser uses the fallback fonts in `:root`.

## 8. Quick reference for an AI coding assistant

- Entry point: `index.html`. Logic: `script.js`. Styles: `styles.css`.
- Products and prices: top of `script.js` (`PRODUCTS`, `PRICES`, `GROUPS`).
- Fixed text: `index.html`, using `data-copy-en` / `data-copy-ar`.
- Dynamic text: `script.js`, using `{en, ar}` objects and `t()`.
- WhatsApp number: `script.js` (`WHATSAPP_NUMBER`) **and** five `href`s plus footer text in `index.html`.
- Prices in text: `script.js` (`PRICES`) **and** the collection heading in `index.html`.
- Never introduce new dependencies, a build step or unverified product claims.
- After a change, run the checklist in section 4, and `tests/browser_test.py` if available.
